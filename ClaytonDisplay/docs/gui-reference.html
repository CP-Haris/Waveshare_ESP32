Clayton Power · ESP32-S3 CAN display

Clayton Display GUI Reference

Complete reference of the current on-device interface, captured pixel-for-pixel from the firmware's rendering engine, as the baseline for a visual redesign. Everything an agency needs: every screen, every state, the token set behind them, and the technical constraints a new design must fit.

What the product does

Context before pixels.

The display is a wall-mounted touch panel for Clayton Power's mobile power systems (vehicles, boats, off-grid). It talks to one or more power units — LPS inverter/charger systems and CB battery packs (BMS) — over a CAN bus, and doubles as a Bluetooth gateway for the companion phone app.

  • Monitor: state of charge, time remaining, power flows for AC in/out, DC output and solar, per connected unit.
  • Control: toggle the inverter and the DC output; adjust unit settings (charge currents, cutoffs, delays) fetched live from the unit.
  • Alert: surface unit error codes with severity, as a list and as interrupting popups.
  • Sleep: the panel blanks after inactivity and wakes on touch or when any unit starts working. The display must feel "off" in a dark cabin.

Hardware and rendering constraints

The redesign has to live inside these. They are firm.

PanelWaveshare ESP32-S3 5" IPS touch, two factory variants: 1024×600 and 800×480. One design must serve both; today a compact layout variant covers the smaller panel.
Color16-bit RGB565. Large soft gradients band visibly — the current design uses only short two-stop vertical gradients on cards.
UI engineLVGL 8.4, software-rendered. Flat surfaces, borders, radii and simple shadows are cheap; full-screen animation and heavy alpha layering are not.
TypographyFonts are compiled to fixed-size bitmaps. Today: Montserrat at 10 / 12 / 14 / 16 / 20 / 24 / 28 / 48 px. Any typeface is possible, but the redesign must specify exact pixel sizes; each size costs flash.
IconsLVGL's built-in FontAwesome subset (the symbols visible in the captures). Custom icons are possible — deliver as monochrome SVG for conversion.
TouchCapacitive, finger operation in a moving vehicle. Current interactive targets are 40–60 px tall; do not go below ~44 px.
Data cadenceLive values refresh every 200 ms. Text fields update in place; layouts never reflow at runtime.
EnvironmentOften the only lit object in a dark cabin. The current theme is deliberately near-black; avoid large bright surfaces.

Navigation model

Four pages and three overlays. Solid arrows are taps; dashed boxes are overlays.

Dashboard

The home screen and the product's face. Everything else is one tap away.

Anatomy

  • Header. Bluetooth icon (accent-blue when the phone app is connected); unit selector pill — shown only when more than one unit is online — with prev/next arrows, an online dot and "1/3 CL2 (1F-AB12)" (index/count, part number, short serial); settings gear.
  • Hero card. State-of-charge ring (270° arc) with the percentage in the center, time-to-full/empty beneath it, battery voltage and current, and charge-source chips (AC / DC / Solar) that appear only while that source is active.
  • System cards. Four fixed cards — DC OUTPUT, SOLAR, INVERTER, CHARGER — each with a status word + dot, one big value, and a smaller V | A detail line.
  • Toggle bar. Two full-width buttons, INVERTER and DC OUT. These are the only controls that change the system's state directly.

Live behavior

  • SOC ring and percentage change color by charge level: > 50 % > 20 % ≤ 20 %.
  • Time-left line: ↑ 2h 14m in green while charging, ↓ while discharging, "Standby" when idle.
  • Toggle buttons have four visual states: dim outline (off), orange outline + "…" (starting/stopping), filled green + "ON", filled red/orange + "!" (fault).

Settings

A two-level menu: category tiles, then a detail list. Values live on the power unit and are fetched over CAN when a page opens.

Errors

Two severities drive all error styling: WARNING and FAILURE / CRITICAL.

The compact panel (800×480)

Same design language, tighter grid: smaller SOC ring, narrower cards, lower buttons, 3-column settings. The redesign should define both sizes from one system.

Shape

  • Corner radii: cards 16–20 px, buttons/tiles 8–16 px, pills fully round.
  • Outer margin 14 px (10 px on the small panel); cards carry 1 px borders and soft dark drop shadows.
  • Status dots (10–12 px circles) accompany every status word.

What we need from the redesign

  • Figma frames at 1024×600 and 800×480 for every screen above, including the fault, BMS and transitional states — not just the happy path.
  • A token sheet: colors, exact font pixel sizes, radii, spacing. Fonts and icons in forms we can convert (any typeface + px sizes; icons as monochrome SVG).
  • All states for the interactive widgets: toggle buttons (off / starting / on / fault), setting rows (idle / pressed / loading), error severities.
  • Respect the constraints table above — RGB565, LVGL 8.4 widgets, ~44 px touch targets, dark-cabin brightness.
